## Multiple Solicitation Codes may be applied to a single itmes. Some examples:
* OA SS - this is two solicitation codes `OA` and `SS`
* OA FI - this is two solicitation codes `OA` and `FI`
* SS KIDS - this is two solicitation codes `SS` and `KIDS`
* OA KIDS - this is two solicitation codes `OA` and `KIDS`

## OA vs. RES (Offered Again vs. Resolicitation):
* OA (Offered Again): The item was already solicited in a previous month's catalog and is being listed a second time with no major changes to its creative team, format, or price—usually because its release date slipped slightly or to drum up extra orders on a hot book. Previously placed retailer orders typically remain active.
* RES (Resolicitation): The item's original solicitation was officially canceled due to major delays or creative/format changes (such as a new cover price, page count, or artist). All previous retailer orders were wiped out, so shops must submit a brand-new order using the new item code if they still want it.

# additional file format details

these may be applicable...

Depending on the era of the .txt file you are parsing, each item line generally follows either a fixed-width/space-padded format (2000s–early 2010s) or a tab-delimited (\t) format (mid-2010s–2025):

Item Code (Diamond SKU): also known as the solicitation code. Always at the start of the line, following the MMMYYNNNN pattern (e.g., APR100001 or NOV240123), occasionally with a trailing letter suffix (A, B, C) for cover variants in later years.

Title & Issue Number: Follows the item code. Watch out for parenthetical notes inside the title string—such as (NOTE PRICE), (OF 4), (C: 0-1-2), or (MR)—which are embedded directly in the title field rather than separated into their own columns.

Inline Flags & Codes: Codes like FI, OS, RES, OA, BI, SS, FO, and KIDS typically appear either in a dedicated narrow column right before the price or appended in parentheses at the end of the title string.

Price Field: Usually the final token on the line. Expect non-numeric strings here—specifically PI (Please Inquire), AR (Ask Retailer), or $TBD—so parse prices as strings first before converting valid currency values ($3.99) to floats or decimals.

 Multi-Line Wrapped Descriptions: In older fixed-width .txt files, long titles or bundle descriptions occasionally wrap onto a second line without a leading Diamond SKU. Check whether a line begins with the ^[A-Z]{3}\d{6} regex pattern; if it does not (and isn't a section header), append it to the previous item's title/notes.

Character Encoding: Older files from the 2002–2012 era frequently use Windows-1252 (CP1252) or ISO-8859-1 rather than UTF-8 (especially for copyright symbols ©, trademark ™, and accented characters in creator names). Opening files with encoding="cp1252" or errors="replace" prevents UnicodeDecodeError crashes.

In-Store Date Subheaders: Newer .txt files (roughly 2018 onward) often insert weekly release date subheaders (e.g., In-Store Date: 04/03/2024) inside each publisher block. Capturing these as state variables lets you tag every parsed comic with its scheduled street date.
